## 18. 社交社区架构设计（v4.0 新增）

> 产品愿景核心差异化：AI 通用助手 + 社交社区一体。AI 助手产生优质内容，社区承载内容流转，形成 UGC 闭环。

### 18.1 社区架构分层

```text
┌────────────────────────────────────────────────────────────┐
│ 1. 内容生产层                                                │
│ - AI 对话产生精彩问答                                       │
│ - 用户点赞触发"设为公开案例"流程                              │
│ - 用户主动创作（AI 辅助写作）                                │
└──────────────────────────────┬─────────────────────────────┘
                               │
                               ▼
┌────────────────────────────────────────────────────────────┐
│ 2. 内容审核层                                                │
│ - showcase 已实现：用户提交→管理员审核→公开                  │
│ - 后续扩展：社区公约自动检测 + 人工审核结合                   │
│ - 内容分类：案例/教程/创作/问答                               │
└──────────────────────────────┬─────────────────────────────┘
                               │
                               ▼
┌────────────────────────────────────────────────────────────┐
│ 3. 内容展示层                                                │
│ - /showcase 公开案例展示（已实现）                           │
│ - 用户主页：展示精选内容 + 个人画像                           │
│ - 内容流：基于兴趣推荐 + 关注关系                            │
│ - 标签体系：技术/生活/创意/学习                              │
└──────────────────────────────┬─────────────────────────────┘
                               │
                               ▼
┌────────────────────────────────────────────────────────────┐
│ 4. 社交互动层                                                │
│ - 点赞/收藏/评论                                            │
│ - 关注/粉丝关系                                             │
│ - 分享/导出（Markdown/长图/PDF）                            │
│ - AI 辅助社交：帮写内容/帮回复/帮找同好                      │
└────────────────────────────────────────────────────────────┘
```

### 18.2 会话分享与导出

**目标**：让用户能将精彩对话分享到社区。

**功能范围**：

- 生成分享链接：指定对话片段生成公开链接
- 生成分享卡片：对话内容 + AI 回答 + 用户评价，渲染为图片卡片
- 导出格式：Markdown / PDF / 长图
- 分享权限：公开 / 仅关注者 / 私密链接
- 扩展 showcase 流程：从"管理员精选"升级为"人人可发布"

### 18.3 用户主页与内容流

**目标**：每个用户有公开主页，展示个人画像和精选内容。

**数据模型**：

| 模型 | 字段 | 说明 |
| --- | --- | --- |
| UserProfile | user_id, display_name, avatar, bio, tags, social_links | 用户公开画像 |
| UserShowcase | user_id, showcase_case_ids, pinned_ids | 用户精选内容列表 |
| Follow | follower_id, followee_id, created_at | 关注关系 |
| ContentFeed | user_id, feed_items[], generated_at | 个性化内容流 |

**内容流推荐策略**：

1. 关注的人的新内容（权重最高）
2. 同标签/同兴趣的热门内容
3. 基于用户记忆画像的语义推荐（与 Phase F 联动）
4. 全站热门内容（兜底）

### 18.4 AI 辅助社交

**目标**：AI 不只是回答问题，还辅助社区互动。

**能力**：

- AI 帮写社区内容：基于用户对话历史，生成可发布的教程/案例/创作
- AI 帮找同好：基于用户记忆画像 + 关注关系，推荐兴趣相投的用户
- AI 帮回复评论：在用户主页评论区，AI 辅助生成回复建议
- AI 内容摘要：长内容自动生成摘要，用于内容流展示

### 18.5 隐私与安全边界

| 内容类型 | 默认可见性 | 用户可控 |
| --- | --- | --- |
| AI 对话历史 | 仅用户本人 | 可分享指定片段 |
| 长期记忆 | 仅用户本人 | 不可公开，不进入社区 |
| 个人知识库文档 | 仅用户本人 | 不可公开 |
| showcase 案例内容 | 公开（审核后） | 可删除/下架 |
| 用户主页画像 | 公开 | 可编辑/隐藏 |

**核心原则**：记忆和知识库是用户私有能力，绝不进入社区；只有用户主动提交并审核通过的案例内容才公开展示。

## 19. 用户共创分身与创作者经济

> 产品愿景核心闭环：用户把自己的技能、经验、认知思维、做事习惯浓缩成一个个"分身"（Persona App）供 Agent 调用；每次调用消耗积分燃料，平台抽成后剩余归创作者。这是社区属性的商业闭环，也是平台从"工具"演进为"生态"的关键。

### 19.1 核心概念定义

| 概念 | 定义 |
| --- | --- |
| 分身（Persona App） | 用户创作的、可供其他用户 Agent 调用的特殊 App。本质是带有 `creator_id` + `fuel_price` + `quality_score` 的 App，复用现有 App 模型与 AppConfig 能力 |
| 燃料（Fuel / 积分） | 调用分身时消耗的计费单位。与现有积分体系共用，但分身调用单独计费 |
| 创作者（Creator） | 发布分身的普通用户。创作者身份是普通用户的一个属性，不是独立角色 |
| 质量分（Quality Score） | 基于使用数据自动计算的分数，决定分身曝光等级和是否自动下架 |
| 冷启动期 | 分身发布后的低曝光观察期，仅创作者自己和受邀者可见可用 |

### 19.2 分身与现有架构的关系

分身不是独立的新系统，而是现有 App/Agent 体系的用户侧扩展：

```text
管理员创建的系统 Agent（资源编排）  ← 系统级，全员可用，不计费
        ↕ 共用 Agent 池归集与治理
用户创作的分身（用户共创）          ← 用户级，按调用计费，走质量筛选
        ↕ 共用 AppConfig / 工具绑定 / 工作流能力
底层能力：AppConfig / 工具池 / 知识库 / 模型路由 / SSE
```

**数据模型扩展**（在现有 App 模型上增加字段，不新建表）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `creator_account_id` | FK(Account) | 创作者账号；系统 Agent 此字段为空 |
| `is_user_created` | bool | 是否用户创作分身；系统资源为 false |
| `fuel_price` | int | 每次调用的燃料积分价格；创作者设定，平台指导区间 |
| `quality_score` | float | 质量分，0-100，系统自动计算 |
| `exposure_level` | enum | cold(冷启动) / limited(低曝光) / normal(正常) / boosted(推荐) / demoted(降级) |
| `publish_status` | enum | draft / pending_review / published / rejected / auto_offline / manual_offline |
| `total_calls` | int | 累计调用次数 |
| `total_revenue` | int | 累计创作者收益（扣除平台抽成后） |
| `review_status` | enum | auto_passed / sampled / reported / approved / rejected |

### 19.3 创作门槛分层设计

创作不应只有一种模式。按用户能力和投入意愿分四层，层层递进：

#### L0 模板填充式（最简单，目标 80% 创作者）

用户填写结构化表单，系统自动转换为 Agent 配置：

| 表单字段 | 转换为 | 说明 |
| --- | --- | --- |
| 分身名称 | App.name | |
| 一句话简介 | App.description | |
| 擅长领域（标签选择） | AppConfig.tags | 从预设标签库选择 |
| 核心方法论（富文本） | AppConfig.preset_prompt 的主体 | 用户用自然语言描述"我怎么做这件事" |
| 处理步骤（动态列表） | 工作流节点提示词 | 用户添加"第一步做什么、第二步做什么" |
| 适用场景（多选） | 触发条件描述 | 告诉系统什么任务适合调用这个分身 |
| 不适用场景（多选） | 排除条件描述 | 告诉系统什么任务不该调用 |
| 燃料定价 | fuel_price | 平台给出指导区间，用户选择 |

系统自动生成：system prompt + 简单工作流 + 默认工具绑定。用户无需理解 prompt engineering。

#### L1 对话式创作（中等，目标 15% 创作者）

用户与"创作导师 Agent"对话，导师通过引导式提问帮用户把隐性经验显性化：

```text
导师：你想创建的分身擅长什么领域？
用户：代码 Review
导师：你做 Code Review 时第一步看什么？
用户：先看命名规范，再看逻辑分支覆盖
导师：你最常发现什么类型的问题？
用户：空指针和边界条件遗漏
...（5-10 轮对话）
导师：我帮你生成了分身草稿，你可以预览并发布
```

对话结束后自动生成结构化 Agent 配置，用户可预览编辑后发布。

#### L2 可视化编排（高级，目标 4% 创作者）

复用现有工作流编辑器：组合工具 + 知识库 + 多步骤 + 提示词。适合有产品思维的高级用户。此能力已存在于 admin 端，需开放给用户侧创作入口。

#### L3 代码级（专业，目标 1% 创作者）

MCP/API 工具开发，适合开发者。此能力已存在。

**设计原则**：L0 是主力路径，必须做到 5 分钟内完成创作并提交。L1/L2/L3 是可选升级路径。

### 19.4 质量门槛与审核成本控制

核心原则：**不靠前端人工审核筛质量，靠市场机制 + 数据驱动筛质量。人工审核只兜底合规与异常。**

#### 19.4.1 准入门槛（创作资格）

不是所有账号一注册就能创作，需满足以下任一条件：

- 账号注册满 7 天 **且** 有效对话 ≥ 10 次（了解平台能力后再创作）
- 被已有创作者邀请（邀请码机制，邀请人承担连带信用责任）

目的：过滤纯薅羊毛账号和随手实验。

#### 19.4.2 发布前置条件（质量自证）

分身从草稿提交发布前，必须满足：

- 创作者自己测试调用 ≥ 3 次，每次有完整输入输出
- 填写了完整的"适用场景"和"不适用场景"
- 通过自动合规检查（敏感词、格式、最小内容长度）

目的：确保创作者自己验证过分身能用，过滤半成品。

#### 19.4.3 冷启动期（低曝光观察）

新发布分身默认进入冷启动期（`exposure_level = cold`）：

- 仅创作者自己和受邀者可见可用
- 冷启动期内收集初始质量数据
- 冷启动期结束（7 天或 ≥ 20 次有效调用）后，根据质量分决定是否进入正常曝光

目的：让分身在低风险环境下积累初始数据，避免劣质内容直接暴露给大量用户。

#### 19.4.4 质量分机制（数据驱动）

基于使用数据自动计算质量分（0-100）：

| 维度 | 权重 | 计算方式 |
| --- | --- | --- |
| 调用完成率 | 30% | 完整执行次数 / 总调用次数 |
| 用户好评率 | 25% | 点赞数 / (点赞+点踩数) |
| 复购率 | 20% | 再次调用的用户占比 |
| 举报率 | 15% | 反向指标，举报次数 / 调用次数 |
| 平均有效性 | 10% | 基于调用后用户是否继续追问修正（低追问=高分） |

质量分阈值与曝光联动：

| 质量分 | 曝光等级 | 自动动作 |
| --- | --- | --- |
| ≥ 85 | boosted | 可进入推荐位，管理员可主动推荐 |
| 70-84 | normal | 正常曝光 |
| 50-69 | limited | 降低曝光，通知创作者改进 |
| 30-49 | demoted | 严重降权，仅搜索精确匹配可见 |
| < 30 或连续 7 天 < 40 | auto_offline | 自动下架，通知创作者 |

#### 19.4.5 审核分级

| 审核类型 | 触发时机 | 方式 | 成本 |
| --- | --- | --- | --- |
| 自动合规审核 | 发布时 | 敏感词、格式、最小内容校验 | 极低 |
| 抽样人工审核 | 曝光提升到 boosted 时 | 管理员抽查内容质量 | 低（只审高曝光） |
| 举报触发审核 | 用户举报时 | 管理员人工介入 | 低（只审被举报） |
| 主动推荐审核 | 管理员推荐到首页时 | 管理员主动审核 | 低（只审推荐位） |

**审核成本控制结论**：自动审核覆盖 100% 发布，人工审核只覆盖高曝光和异常内容，预计人工审核量 < 总发布量的 5%。

### 19.5 积分经济模型

#### 19.5.1 定价机制

- 创作者在平台指导区间内设定 `fuel_price`（如 1-50 积分/次）
- 平台指导区间按分身类型分档：简单对话型 1-10，工具组合型 5-30，专业知识型 10-50
- 创作者可随时调整价格，但调整不影响已发生的调用

#### 19.5.2 抽成与结算

```text
用户调用分身 → 消耗 fuel_price 积分
  → 平台抽成（第一阶段 20%）
  → 创作者获得 80%
  → 计入 creator_revenue
```

- 平台抽成比例第一阶段统一 20%，后续可按创作者等级浮动
- 创作者收益累计到账户余额
- 余额达到提现阈值（如 1000 积分）后可申请提现
- 提现需人工审核（防刷）

#### 19.5.3 防刷机制

| 风险 | 防御措施 |
| --- | --- |
| 创作者自刷调用 | 创作者调用自己分身不计收益 |
| 新账号刷调用 | 注册 < 7 天账号调用不计创作者收益 |
| 短时重复调用 | 同一用户 10 分钟内重复调用同一分身只计 1 次收益 |
| 互相刷量 | 异常互调模式检测（A 只调 B、B 只调 A）自动冻结收益 |
| 积分套利 | 提现审核 + 最低提现阈值 + 异常收益冻结 |

### 19.6 用户侧创作入口

用户创作入口与配置中心分离，独立为"创作工作室"：

| 路由 | 定位 | 谁可见 |
| --- | --- | --- |
| `/studio` | 创作工作室首页（我的分身列表 + 创建入口） | 满足准入门槛的用户 |
| `/studio/create` | L0 模板填充创作页 | 同上 |
| `/studio/create/guided` | L1 对话式创作页 | 同上 |
| `/studio/:id/edit` | 编辑分身草稿 | 分身创作者本人 |
| `/studio/revenue` | 收益仪表盘（调用数据、收益、提现） | 创作者 |
| `/creator/:user_id` | 创作者公开主页（已发布分身 + 创作者画像） | 全部用户 |

**与配置中心 `/space/*` 的关系**：配置中心是管理员入口，创作工作室是用户入口。两者完全独立，不共享路由和组件。

### 19.7 管理端资源运营板块的新定位

资源运营板块从"上下架到商店"升级为"用户创作内容审核 + 创作者经济管理 + 商店运营"：

| 职责 | 具体操作 |
| --- | --- |
| 内容审核 | 审核分身发布（抽样）、举报处理、违规下架 |
| 质量监控 | 监控分身质量分分布、异常波动告警、批量降级 |
| 创作者管理 | 创作者信用分、违规处理、收益冻结/解冻 |
| 商店运营 | 推荐位配置、分类管理、活动扶持、定价指导区间调整 |
| 积分经济 | 抽成比例配置、提现审核、防刷规则配置、收益报表 |

资源运营与资源编排的职责边界：

| 维度 | 资源编排 | 资源运营 |
| --- | --- | --- |
| 管理对象 | 系统级资源（管理员创建的 App/Tool/Workflow/MCP） | 用户创作分身 + 商店运营 |
| 核心操作 | CRUD（创建/编辑/删除） | 审核/上下架/推荐/收益管理 |
| 数据所有权 | 系统资源实体由编排板块编辑 | 分身的 publish_status/exposure_level 由运营板块编辑 |
| 与分身关系 | 不涉及用户分身 | 分身审核和质量管理的唯一入口 |

### 19.8 分身入池与治理

用户创作的分身发布后，自动进入"用户创作 Agent 子池"，参与动态归集：

```text
Agent 池
├── system Agent 子池（管理员创建，资源编排管理）
├── user_persona 子池（用户创作分身，资源运营审核管理）
└── 其他业务子池
```

治理策略透传：
- 分身继承 `risk_level`、`routing_priority` 等治理字段
- 池治理板块对分身有只读展示权，不直接编辑分身内容
- 池治理可设置"用户创作分身"子池的全局策略（如限流、最大并发）
- 分身的 `exposure_level` 由资源运营管理，`risk_level` 由池治理管理，两者独立

### 19.9 第一阶段范围与后续演进

**第一阶段（MVP）**：

- L0 模板填充式创作
- 自动合规审核 + 举报触发人工审核
- 质量分基础版（完成率 + 好评率 + 举报率）
- 冷启动期机制
- 基础积分计费与创作者收益
- 资源运营板块：分身审核列表 + 举报处理

**后续演进**：

- L1 对话式创作（创作导师 Agent）
- L2 可视化编排开放给用户
- 质量分完整版（复购率 + 有效性）
- 创作者等级体系（影响抽成比例和曝光加权）
- 邀请码机制与连带信用
- 提现系统对接
- 创作者数据分析仪表盘
- 分身版本管理与 A/B 测试
