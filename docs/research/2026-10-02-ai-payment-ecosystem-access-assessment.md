# AI 支付生态接入评估（微信 AI 支付 / 支付宝 Agent Pay）

> 调研时间：2026-10-02 · 状态：**调研结论，非权威、不代表当前实现**（AGENTS.md 规则：`docs/research/` 为调研快照，不作为系统现状依据）
> 背景：为「钰见我」后续支付功能评估「Agent 替用户下单购物」类设想的可行性，本文聚焦**以供给侧（商户/服务供应方）身份接入微信与支付宝的 AI 支付生态**这一唯一合规路径。

## 1. 结论速览

| 设想路径 | 结论 | 原因 |
|---|---|---|
| 公司公户做资金中转站，替用户向第三方平台下单 | ❌ 不可行（合规红线） | 构成"资金归集→代付"二清/无证清算，反洗钱冻结风险极高 |
| 用户充值进持牌第三方（易宝等）分账体系，站内闭环消费 | ✅ 合规可行 | 不碰用户钱，清算归持牌方；但仅限自营/已签约商户 |
| **作为供应方接入微信 AI 支付 / 支付宝 Agent Pay** | ✅ **当前唯一正门** | 用户用自己的账户（AI 专属卡/支付宝）直接付，Agent 只负责选品下单，钱不经过我方 |

**一句话**：与其"撬淘宝/京东的账号去代下单"（账号风控 + 平台未开放接口 + 违规代操作三重死路），不如**把我方自身（或已签约商户）的数字服务封装成"可被 Agent 调用的商户 Skill / 商品供应方"**，挂上微信/支付宝的 AI 支付生态，让别的 Agent 来调用、由我方收款。这才是 AI 支付能真正落地到本项目的入口。

## 2. 微信侧：微信 AI 支付 / SkillHub（SkillPay）

官方产品定义：微信 AI 支付是微信支付为智能体场景专门设计的支付能力。当智能体调用的**商户 Skill** 声明需要使用支付能力时，智能体可唤起微信 AI 支付完成支付请求。角色分工：智能体（唤起商户 Skill）、商户（在 SkillHub 入驻并接入）、用户（开通智能体专用的 **AI 专属卡**，资金与微信支付主账户**隔离**，AI 支付只能从专属卡余额划扣）。

来源：[微信支付商户文档中心-产品介绍 AI支付](https://pay.weixin.qq.com/doc/v3/merchant/4035576700)

### 2.1 接入门槛与步骤

腾讯 SkillPay（2026-07 上线，首次将技能分发、Agent 调用与技能支付在同一条链路上打通）给出的企业三步路径：

1. **企业认证 + 绑定微信支付账户**：在 SkillHub 完成企业认证，绑定微信支付账户，完成 SkillPay 入驻；
2. **封装 Pay Skill**：准备 Skill 上传，设置价格与计费模式，通过简易改造把已有 Skill 封装成 Pay Skill；
3. **上架发布**：在 SkillHub 上架发布，发布后自动具备向所有接入 Agent 收费的能力。

官方强调"**不用重写业务、不用自建支付链路，定价权和收款权完全归企业**"。

来源：[腾讯云 SkillPay 上线，Skill 能挣钱了](http://news.qq.com/rain/a/20260716A09SXS00)、[央广网：腾讯上线 SkillPay 支付体系](http://tech.cnr.cn/techgd/20260717/t20260717_527715580.shtml)

底层资质兜底：微信 AI 支付复用标准微信支付商户能力，商户主体需符合微信支付主体类型要求（个体工商户、企业、事业单位、政府机关、社会组织等）。

来源：[微信支付-开发接入准备 APP支付](https://pay.weixin.qq.com/doc/v3/merchant/4015478291)

### 2.2 支付体验机制（笔笔确认）

- **笔笔确认模式**：用户从智能体调用商户服务后下的每一笔订单，需**扫码至微信 LiteApp，由用户授权确认该笔订单是否支付**，并输入支付密码验证身份——**不是 AI 静默划扣，用户对每一笔保留最终决定权**；
- **AI 专属卡**：资金独立于微信支付主账户，只能从专属卡余额划扣。

来源：[微信支付商户文档中心-产品介绍 AI支付](https://pay.weixin.qq.com/doc/v3/merchant/4035576700)

### 2.3 应用场景

- **智能体购物结算**：用户在智能体对话中完成选品后，商户 Skill 向微信支付下单，并在对话流中唤起支付卡片，用户按卡片指引开通并使用 AI 专属卡支付；
- **Skill 付费**：商户提供的 Skill 服务接入微信 AI 支付，在智能体调用过程中发起支付动作。

来源：[微信支付商户文档中心-产品介绍 AI支付](https://pay.weixin.qq.com/doc/v3/merchant/4035576700)

## 3. 支付宝侧：Agent Pay（智能体支付）

官方定位：Agent Pay 连接智能体平台与商品服务商家，让 Agent **在用户授权下**完成下单、支付与凭证回传，衔接商品与服务交付。适合人群：办公与移动智能体平台、商品与生活服务商家。

来源：[支付宝 Agent 支付-产品介绍](https://aipay.alipay.com/docs/subscribe/introduce.html)、[支付宝 Agent 支付官网](https://aipay.alipay.com/)

### 3.1 准入条件（硬门槛）

1. **账号类型**：仅支持**支付宝企业账号**；
2. **经营类目（MCC）受限**，官方列出的适用类目集中在数字服务/工具/SaaS 方向：
   - 网络通讯-软件开发服务（B0121）
   - 网络通讯-互联网数据服务（B0120）
   - 网络通讯-信息检索服务/网络论坛（B0113）
   - 网络通讯-其他在线应用或综合类服务（B0125）
   - 商业生活服务-在线工具（B0112）
   - 生活缴费-话费/网络充值 等
   - 审核通过后方可使用
3. **收单前置**：需已签约「APP 支付」或「电脑网站支付」收单产品码。

来源：[支付宝 Agent 支付-产品介绍（MCC 类目）](https://aipay.alipay.com/docs/subscribe/introduce.html)

开户资料准备参考：营业执照或其他主体证明、统一社会信用代码、主体名称、经营地址、法定代表人或负责人信息、经办人身份及联系方式、结算账户资料；需注意证照名称、签约主体与结算账户主体一致性（涉及品牌方/技术服务商时尤为关键）。

来源：[Machine Pay 商户开通要准备哪些资料](https://aipay.alipay.com/article/358)

### 3.2 技术集成路径（与本项目最契合的部分）

**移动端智能体接入**（商家此前在 APP 经营）：
- 前置：已签约 APP 支付收单产品码；
- 关键步骤：商家调用支付宝**预下单接口**（`alipay.trade.order.prepay`）发起收单，将返回的**预下单号 prepayId** 交给智能体平台，由智能体平台推进支付。

**PC 端智能体接入**（商家此前在电脑网站经营）：
- 前置：已接入支付宝电脑网站支付；
- 改造：在原有系统外增加一个「**商家下单 Skill**」，由 Agent 唤起，支持选品、下单、支付流程（对接 `alipay.trade.page.pay`）；
- 推进支付：取 `pageRedirectionData` 字段，用 `alipay-bot trigger-payment-signal` 压缩为支付短链，再用 `alipay-bot submit-payment` 唤起支付宝 Skill 推进支付——**支付宝接管整体支付流程，引导用户完成支付**；
- 联调：`npx -y @alipay/agent-payment@latest install`；
- 官方提供现成 Demo：[支付宝电脑网站支付 Demo - 运势预测（Node.js）](https://github.com/alipay/ai/tree/main/code_example/page-pay-demo-with-agentpay)（含商家下单 Skill、支付上翻适配代码）。

来源：[商家接入移动端/PC 端智能体（Agent Pay 文档）](https://aipay.alipay.com/docs/agent-pay/skillpay.html)

## 4. 关键边界（必须清楚，避免再绕弯路）

1. **商家有支付宝/微信收款渠道 ≠ 支持 AI 付**：前者只是"消费者付款能走该通道"（收单），后者要求商户把**可被 Agent 调用的下单/商品/履约接口**开放给 AI 支付生态。目前淘宝、京东、拼多多、微信小店**均未开放**这条"可被代理下单"链路；
2. **同一商户也未必全商品支持**：以美团生活助手实测为例，部分商品支付通道未带 AI 专属卡选项（`WeixinPay-Required` 字段为空），下单成功仍须跳转美团 App/小程序付款；
3. **"跨平台"在两个含义上都不成立**：既不能跨淘宝/京东/拼多多这类零售平台代下单，也不能跨微信↔支付宝体系互付（各自封闭，用户须用自己的对应账户授权）。

## 5. 对钰我见的落地建议

### 5.1 定位：做「供给侧」，不做「代购壳」

放弃"嵌 H5 / 虚拟机跑 App / 长期复用登录态"等代操作类方案（账号风控 + 平台条款违规 + 支付必须唤起支付宝/微信，三重死路）。正门是：**把我方自己的数字服务（或已签约商户的商品）封装为可被 Agent 调用的商户能力**。

### 5.2 与本项目现有能力的映射

- 本项目已具备 **Skill 机制**（skill 池、`skill:create/delete` 权限、可被 Agent 调用的工具/Skill 体系）——这与支付宝「商家下单 Skill」、微信「商户 Skill」形态天然同构，封装改造成本相对低；
- 最贴合支付宝 MCC 的类目是**软件开发服务（B0121）/ 在线工具（B0112）**，即把钰我见的原生数字能力（如内容生成、分析、工具调用）作为 Skill 出售并收费；
- 微信侧对应 SkillHub 的 **Skill 付费**场景：上架 Pay Skill 即可向所有接入的 Agent 收费。

### 5.3 商业模式与收益路径

| 场景 | 资金路径 | 我方角色 |
|---|---|---|
| 用户在我的 Agent 内买我方套餐/权益 | 用户支付宝/微信账户 → 我方商户号 | 供应方 + 收单方 |
| 第三方 Agent 调用我方 Pay Skill | 第三方用户账户 → 我方商户号 | Skill 供应方（SkillPay 定价权/收款权归我方） |
| 我方 Agent 调用第三方商户 Skill | 我方用户账户（AI 专属卡/支付宝）→ 第三方商户 | Agent 平台方（引流 + 生态位） |

### 5.4 合规底线（写进产品设计）

1. **我方绝不归集、代付用户资金**——用户钱从用户自己的账户直接付给收款商户，我方无资金池；
2. **保留"笔笔确认"**：每笔支付由用户本人扫码/输密码授权，Agent 不得静默扣款（这是监管与两家支付平台共同的方向，也是产品信任基础）；
3. **站内虚拟资产（返佣/余额）只限站内消费**，不对外支付——虚拟余额对外结算即资金池，触碰二清红线；
4. **用户数据与支付授权分离**：支付授权走官方收银台，我方不截留支付凭证/密码类敏感信息。

## 6. 行动清单（建议立项顺序）

- [ ] **决策层评审**：确认走"供给侧接入"路线，放弃"代购壳"路线（本报告 §1、§4 为决策依据）
- [ ] **主体准备**：确认我方企业主体可申请微信支付商户号 + 支付宝企业账号（MCC 类目匹配软件开发/在线工具）
- [ ] **先走微信 SkillHub（SkillPay）**：成本最低、无需自建支付链路，封装 1 个现有 Skill 做试点验证闭环
- [ ] **再走支付宝 Agent Pay**：签约电脑网站支付收单产品码 → 搭「商家下单 Skill」+ `alipay-bot` 联调（官方 Demo 可直接参考）
- [ ] **产品设计**：定义"笔笔确认"交互、AI 专属卡开通引导、订单与售后在 Agent 侧的编排
- [ ] **合规留档**：向持牌支付机构/律师确认分账与类目合规（非法律意见可替代项）
